## 0. v2.0 → v2.1 검토 로그

원천 목표 — *"AI로 개발되는 소스 저장소를 **관리**하고, 고성능~저성능 AI가 쓸 때의 **규칙**과 **형태**를 관리한다"* — 에 v2.0을 대조한 결과:

| 목표 축 | v1 | v2.0 | 판정 |
|---|---|---|---|
| (B) 규칙 관리 | SSOT·배포·150줄 게이트·시크릿 | 부패 탐지 | 충실 |
| (C) 형태 관리 | 프로파일·팩·맵·MCP | `--about`·`--diff`·공변경·eval | 충실, 더 깊어짐 |
| (A) 저장소 관리 | **없음** (`check`는 컨텍스트 산출물만 검사) | 부패 탐지 1건만 걸침 | **공백** |

v2.0은 잘하는 축(C)에 5개 중 4개를 쓰고 빈 축(A)에는 1개, "저성능" 전제 검증에는
0개를 썼다. 또 1순위였던 `--about`의 효과는 **가설**인데, 그것을 판정할 지표는
5순위 `eval`에 있어 순서가 뒤집혀 있었다. 외부 조사(references.md)로 다음이
추가로 확인됐다:

- 파일 수준 위치 찾기는 BM25만으로 재현율 87.7%(Top-30) — `--about`의 임의 가중치를
  BM25로 대체하고, 임베딩 비도입을 정량 근거로 못 박는다.
- Agentless의 계층적 위치 찾기(파일→함수→편집 지점)가 4계층과 같은 구조 —
  설계 정당성 확보.
- ETH의 AGENTS.md 연구가 "부패한 규칙 = 비용만 내는 규칙"을 뒷받침 — 규칙 부패
  탐지의 우선순위 상향.
- 아키텍처 피트니스 함수(dependency-cruiser·import-linter) 계열이 (A)축의 확립된
  선례 — 제약 검증을 새 발명이 아니라 축소·언어중립 구현으로 위치시킨다.

**v2.1의 변경**: (A)축을 1급 항목으로 승격(§4.2), `eval`을 1순위로 이동(판정 수단
먼저), `--about`을 BM25 기반으로 개정, 로컬 LLM 실측을 로드맵 정식 항목으로,
항목마다 외부 근거를 명시.

## 1. 진단

측정 전 라운드([findings.md](../eval/findings.md))에서 성패를 가른 것은 **필요한
파일이 팩 안에 있었는가** 하나였다. q2 통과는 `pdm.py`가 우연히 랭킹 1위였기
때문이고, q1 실패는 `his.py`가 모듈 밖이었기 때문이다(4차: 모듈 팩 0/4 vs 저장소
전체 팩 4/4). v1의 선별은 **정적이고 과제와 무관**하다.

두 번째: **저장소 자체의 건강을 아무도 보지 않는다.** `check`의 4항목은 전부
컨텍스트 산출물(규칙 길이·동기화·맵 신선도·시크릿)이다. AI가 써 내려가는 코드가
규칙을 지키는지, 같은 기능이 두 번 구현되는지, 관리되지 않는 영역이 자라는지는
검사 대상이 아니다. 이것이 원천 목표의 첫 구절이 요구하는 것이다.

세 번째: 규칙(Tier 0)은 모든 프로파일에 주입되므로 **부패의 파급이 가장 크다**.
ETH 연구는 컨텍스트 파일이 비용을 20% 올리면서 성능을 못 올리는 조건을
보여줬는데, 사실이 아니게 된 규칙이 바로 그 조건이다.

## 2. 설계 원칙 추가

기존 6원칙(백서 §3)에 더한다.

7. **컨텍스트는 과제 형태를 띤다.** 선별 기준은 `중요도`에서 `중요도 × 과제
   관련도`로. (참고: Agentless의 계층적 위치 찾기, aider의 편집 파일 기준 개인화)
8. **도구 수는 늘리지 않는다.** MCP 도구 5종 유지, 기능은 파라미터로. (참고:
   SWE-agent ACI — 단순성·간결성·가드레일)
9. **저장소 건강은 컨텍스트와 같은 게이트에서 검사한다.** 별도 도구가 아니라
   `check`의 항목으로 — 커밋 시점에 규칙 준수와 드리프트가 함께 잡혀야 "관리"다.

## 4. 항목별 설계

### 4.1 측정 하네스의 제품화 — `ctxkit eval` (1순위: 판정 수단 먼저)

**문제.** `eval/run.mjs`는 패키지에 포함되지 않아 도입 팀은 프로파일을 감으로
고른다. 그리고 이후 항목(§4.4 등)의 채택/기각을 판정할 지표가 제품에 없다.

**인터페이스.**

```sh
ctxkit eval --init                        # tasks.yaml 템플릿
ctxkit eval --tasks tasks.yaml --dry-run  # 모델 호출 없이 포함률만 (무료)
ctxkit eval --tasks tasks.yaml --profiles mid,light --models haiku,sonnet \
  --custom "qwen=ollama run qwen3:14b" --module risk --out results.md
```

**설계.**
- 과제에 `expect_file`(정답이 들어 있는 파일) 필드를 추가한다. `--dry-run`은
  프로파일별 팩을 만들어 **정답 파일 포함률**만 계산한다 — 모델 호출 없는 무료
  사전 지표이며, 검색 단계를 따로 채점하는 RepoBench-R의 축소판이다.
- 모델을 호출하는 유일한 명령이므로 실행 전 예상 호출 수(프로파일×모델×과제)를
  출력하고 `--yes` 없이는 확인을 받는다.
- 결과 표에 컨텍스트 토큰·소요 시간·답변 발췌를 남긴다(현행 유지).

**구현 지점.** `eval/run.mjs` → `src/eval.ts` 이관, `cli.ts` 명령 추가. 기존
스크립트는 얇은 래퍼로 남긴다.

**검증.** 외부 저장소에서 `npx @seanshin/ctx-kit eval --init` → 과제 3개 →
`--dry-run` → 실행이 한 번에 되는지.

**참고.** RepoBench-R, CodeRAG-Bench(검색 방식 A/B 방법론). · **규모** 1일.

### 4.2 저장소 건강 검사 — (A)축 (2순위)

**문제.** AI가 쓴 코드가 규칙을 지키는지, 드리프트가 쌓이는지 아무도 보지 않는다.

**인터페이스.** 새 명령이 아니라 `check`의 항목이다(원칙 9). 설정에 선언한다:

```yaml
constraints:                                   # v2.1 신규(선택)
  - id: discount-single-source
    symbol: "apply_discount"                   # 이 심볼의 정의는
    only_in: ["src/pricing/discount.py"]       #   여기에만 있어야 한다
  - id: no-db-from-ui
    from: ["src/ui/**"]                        # 이 경로의 파일은
    must_not_import: ["src/db/**"]             #   저기를 import하면 안 된다
  - id: no-secrets-in-config
    forbid_pattern: "password\\s*="            # 이 패턴이 나타나면 안 된다
    in: ["config/**"]
health:
  duplicates: warn        # 중복 정의 심볼 (기본 warn)
  orphans: warn           # 외부 참조 0인 소스 파일 (기본 warn)
  coverage: info          # 어느 모듈에도 속하지 않는 파일 (기본 info)
```

**알고리즘.**
1. **제약 준수.** 세 종류만 지원한다 — `only_in`(심볼 정의 위치), `must_not_import`
   (경로 간 import 금지), `forbid_pattern`(경로 내 패턴 금지). 심볼 정의는 기존
   추출기, import는 언어별 `import/from/require` 한 줄 정규식으로 잡는다.
   의도적으로 좁다: dependency-cruiser·import-linter의 **언어 중립 축소판**이며,
   정밀 검사가 필요하면 그 도구들을 어댑터로 부른다.
2. **중복 구현.** 같은 이름의 함수/클래스가 서로 다른 파일에 정의되고 시그니처가
   같으면 보고. 컨텍스트를 못 본 에이전트가 만드는 전형적 산물이다. 이미 있는
   심볼 인덱스에서 바로 나온다.
3. **고아 파일.** 외부 참조 점수 0인 소스 파일(테스트·엔트리포인트·설정 제외).
   참조 점수는 이미 계산 중이다.
4. **커버리지.** `modules` 글롭에 하나도 안 걸리는 소스 파일 목록 = 관리되지 않는
   영역. `modules`가 비어 있으면 건너뛴다.

**수준.** 제약 위반은 `fail`(규칙이 깨졌다), 중복·고아는 기본 `warn`(오탐 여지 —
실전에서 오탐률을 본 뒤 승격), 커버리지는 `info`.

**규칙 문서와의 연결.** AGENTS.md의 Constraints 절에 `<!-- ctxkit:constraint
discount-single-source -->` 주석을 달면 `check`가 문서의 제약이 설정에 실제로
등록돼 있는지도 확인한다 — 문서상 규칙과 검사되는 규칙의 괴리를 막는다.

**구현 지점.** `core/check.ts`에 항목 4종, `core/config.ts`에 스키마, 언어별
import 정규식은 `adapters/symbols.ts` 옆에 `adapters/imports.ts`.

**검증.** 픽스처에 위반을 인위 주입해 100% 검출, ctx-kit·실전 저장소에서 오탐률
측정. 실전 저장소의 AGENTS.md 제약("할인 배율은 discount.py에만" 류)을
`constraints`로 옮겨 실제로 잡히는지 확인.

**참고.** dependency-cruiser(MIT), import-linter(BSD-2), ArchUnit(참고만) — 피트니스
함수 계열; jscpd·knip·vulture — 정밀 어댑터 후보. · **규모** 1~1.5일.

### 4.3 규칙·설정 부패 탐지 (3순위)

**문제.** 규칙이 존재하지 않는 경로·안 도는 명령을 가리켜도 게이트가 통과한다.

**인터페이스.** `ctxkit check` 기본 포함, `--run-commands`는 옵트인.

**알고리즘.**
1. AGENTS.md 백틱 구간 추출. `/` 포함 또는 알려진 확장자 → **경로 후보**, 존재
   확인(글롭은 매치 0건이면 실패).
2. `## Commands` 절 안에서 알려진 러너(`npm pnpm yarn pytest cargo go make docker
   uv poetry`)로 시작 → **명령 후보**. 기본은 러너가 PATH에 있는지만(`warn`),
   `--run-commands`일 때 실행(타임아웃 120초, 비영점 종료 `fail`).
3. `context.config.yaml`의 모듈 글롭 매치 0건 → `fail`(설정 부패).

**단계적 승격.** 경로 검사는 오탐(백틱 안 코드 조각) 가능성 때문에 `warn`으로
시작, 실전 2곳 오탐 0 확인 후 `fail`.

**구현 지점.** `core/check.ts`. · **검증.** 부패 주입 100% 검출, 실전 오탐 0.
**참고.** ETH AGENTS.md 연구(부패 규칙의 비용). · **규모** 반나절.

### 4.4 질의 기반 팩 — `--about` (4순위, §4.1 지표로 판정)

**문제.** "할인 계산을 고쳐줘"에도 팩은 저장소 상위 파일을 준다.

**인터페이스.**

```sh
ctxkit pack --about "gold tier 할인 배율" [--profile light] [--module risk]
```
MCP: `make_pack`·`get_module_context`에 `about?` 파라미터(도구 수 불변).

**알고리즘 (v2.0에서 개정).** 임의 가중치 대신 **BM25**를 쓴다 — SWE-bench 계열에서
파일 수준 위치 찾기의 검증된 기준선(Top-30 재현율 87.7%)이다.

```
문서 D(F) ← 경로(가중 3회 반복) + 심볼명(2회) + 본문   # 필드 가중을 반복으로 근사
terms    ← 질의 토큰화(공백·구두점 분리, 2자 미만·불용어 제거, 소문자)
bm25(F)  ← Σ_t idf(t) · tf(t,F)·(k1+1) / (tf(t,F) + k1·(1−b+b·|D(F)|/avg|D|))   # k1=1.2, b=0.75
score(F) ← normalize(ref(F)) + w · normalize(bm25(F))                            # w 초기 2
```

질의가 없으면 v1과 동일(회귀 없음). 한국어 질의는 형태소 분석 없이 부분 문자열
일치를 허용한다(§8 열린 질문).

**구현 지점.** `core/retrieve.ts`(BM25, 무의존 ~80줄), `core/repomap.ts`의
`rankFiles(config, files?, query?)`, `core/pack.ts` 헤더에 `about="…"` 기록.

**검증 — 채택/기각 기준.** §4.1 `--dry-run` 포함률로 판정한다. 목표: 질의 관련
과제에서 정답 파일 포함률 ≥ 90%, `--about` 미사용 대비 유의한 상승. 4차 측정의
q1(모듈 밖 심볼)이 `--module risk --about "request_memo"`로 회복되는지가 대표
사례. 상승이 없으면 이 기능은 넣지 않는다.

**참고.** BM25(Robertson & Zaragoza 2009), SWE-bench BM25 기준선, Agentless 위치
찾기, aider 개인화 맵. · **규모** 반나절(+BM25 구현 반나절).

### 4.5 변경 중심 팩 — `--diff` (5순위)

**인터페이스.** `ctxkit pack --diff HEAD~3` · `--diff --staged` · `--diff origin/main...`

**알고리즘.** 시드 = `git diff --name-only` 소스 파일. 확장 = 시드 심볼을 참조하는
파일 상위 10. 시드는 예산을 넘겨도 **자르지 않고 경고와 함께 전부 포함**(변경
파일이 빠진 리뷰 컨텍스트는 무의미). 거대 diff는 시드 경로 목록 + 상위 원문만
담는 열화 모드. 헤더에 범위·시드 기록.

**구현 지점.** 새 `core/git.ts`(diff 목록·저장소 판별·§4.7 공용), `core/pack.ts`.
**검증.** 변경 파일 포함률 100%, 확장 파일이 실제 호출자인지 표본 확인.
**참고.** aider의 편집 파일 기준 맵 개인화. · **규모** 반나절.

### 4.6 로컬 LLM 실측 — 전제 검증 (6순위, 기능 아님)

**문제.** "저성능까지"가 목표의 절반인데 소형 모델 측정은 haiku **대리**뿐이다.
기능을 더해도 이 공백은 메워지지 않는다.

**절차.** ollama 설치(사용자 결정, 모델 ~9GB) → `ctxkit eval --custom
"qwen=ollama run qwen3:14b"`로 1·2차 매트릭스 재실행 → `findings.md` 5차 기록.
`num_ctx`를 팩 토큰 이상으로 설정하고, CJK 과소평가(§G 참고) 때문에 실제 잘림
여부를 함께 기록한다.

**성공 기준.** light 프로파일에서 실제 로컬 모델이 구현 세부 과제를 통과 —
"컨텍스트 형태가 모델 등급을 이긴다"는 핵심 주장이 대리 없이 성립하는지.

### 4.7 공변경 랭킹 (7순위, 기각 조건 있는 실험)

**설정.** `ranking: { cochange: false, commits: 500 }` (기본 꺼짐).

**알고리즘.** `git log --format=%x00%H --name-only -n N` → 커밋별 변경 집합 C
(|C| > 50 제외) → 공변경 행렬. 시드 집합 S(모듈·diff·질의 상위)가 있을 때만
`score(F) += γ·normalize(Σ_{s∈S} co[F][s]/|S|)`, γ 초기 1. 전역 맵에는 미적용.

**채택/기각.** 실전 저장소에서 정적 참조 상위 20과 공변경 상위 20의 차집합에
"관련은 있지만 참조는 없는" 파일(설정↔코드, 스키마↔마이그레이션, 문서↔구현)이
실제로 나타나면 채택, 아니면 기각. 얕은 클론·이력 50커밋 미만은 자동 비활성.

**참고.** Zimmermann et al. 2004/2005(ROSE — 프로그램 분석이 못 잡는 결합),
Tornhill(핫스팟·시간적 결합; code-maat은 GPL이라 코드 차용 금지). · **규모** 1~2일.

## 5. 설정 스키마와 호환성

추가 필드는 전부 **선택적**, `version: 1` 유지. 로더는 알 수 없는 키를 무시하므로
구버전이 v2.1 설정을 읽어도 깨지지 않고, v2.1이 v1 설정을 읽으면 새 기능이 꺼진
채 동작한다.

```yaml
version: 1
constraints: []          # §4.2
health: { duplicates: warn, orphans: warn, coverage: info }
ranking: { cochange: false, commits: 500, query_weight: 2 }
```

## 7. 비목표

- **임베딩·벡터 검색.** 파일 수준 위치 찾기는 BM25만으로 재현율 87.7%(Top-30).
  의존성·인덱스 상태·오프라인 불가를 감수할 이득이 정량적으로 없다. 의미 검색은
  Serena를 나란히 등록하는 기존 답.
- **Serena 래핑.** 두 MCP 서버는 클라이언트에서 합쳐진다.
- **LLM으로 규칙 자동 작성.** ETH 연구: −3% 성능, +20% 비용.
- **언어별 정밀 린터의 재구현.** 제약 검사는 언어 중립 축소판까지만; 정밀도는
  dependency-cruiser·import-linter·jscpd 어댑터로.
- **웹 UI·대시보드.** 소비자는 모델과 CI다.
