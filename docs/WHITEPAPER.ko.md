# ctx-kit: AI 코딩 에이전트를 위한 능력 계층형 코드베이스 컨텍스트

*백서 · v0.2.0 · 2026년 9월 · [English](WHITEPAPER.md)*

## 요약

AI로 개발되는 저장소는 능력이 크게 다른 모델들이 함께 소비한다 — 도구로
탐색하는 프론티어 에이전트, 32~128K 윈도의 중형 모델, 프롬프트 한 번이 전부인
소형 로컬 LLM. ctx-kit은 프로젝트 컨텍스트의 단일 원본을 유지하고, 각 모델
계층이 실제로 쓸 수 있는 형태로 3가지 인터페이스(MCP 서버, CLI, 일반
파일)를 통해 제공한다. 합성 픽스처와 소스 308개 실전 저장소 양쪽의 통제
측정에서, 과제 성패를 가른 것은 **모델 등급이 아니라 컨텍스트 형태**였다:
구현 세부 과제는 파일 원문이 없으면 모든 모델 계층에서 실패했고, 있으면 모든
계층에서 통과했다. 한편 프론티어 에이전트는 같은 과제를 벌크 컨텍스트 없이
표적 MCP 호출 2회로 해결했다.

## 1. 문제

설계의 동기가 된 세 가지 관찰:

1. **모델 이질성은 항구적이다.** 비용·프라이버시·지연 때문에 소형 로컬 모델은
   프론티어 에이전트와 같은 코드베이스에서 계속 함께 쓰인다. 한 가지 소비
   방식만 가정한 컨텍스트 도구는 나머지를 놓친다.
2. **컨텍스트 파일이 대규모로 잘못 쓰이고 있다.** 138개 저장소 대상 공개
   평가에서 LLM이 생성한 에이전트 지침 파일은 과제 성공률을 *낮추면서* 추론
   비용을 20% 이상 올렸다. 규칙은 짧고, 사람이 검증했고, 코드가 표현할 수
   없는 것으로 제한되어야 한다.
3. **도구 종속은 피할 수 있다.** AGENTS.md 표준(Linux Foundation 이관,
   Claude Code·Codex CLI·Cursor·Copilot·Gemini CLI 등이 네이티브 지원)과
   MCP(Model Context Protocol)가 벤더 중립 설계를 현실화했다.

## 2. 설계 원칙

- **단일 원본(SSOT).** 규칙은 `AGENTS.md`에만 있고 도구별 파일(`CLAUDE.md`,
  `.cursorrules`, …)은 생성 사본 또는 심링크다. ctx-kit이 만들지 않은 파일은
  `--force` 없이 절대 덮어쓰지 않는다.
- **코드가 말할 수 없는 것만 적는다.** 명령·제약·불변식·도메인 용어집,
  150줄 이하 — 게이트가 강제한다.
- **사람 작성과 파생 산출물의 엄격한 분리.** 맵과 팩은 코드에서 재생성하며
  손으로 고치지 않는다.
- **능력 프로파일.** 설정 하나가 모델 계층별로 어떤 섹션을 어떤 토큰 예산으로
  주입할지 선언한다.
- **파일이 바닥이다.** 모든 기능은 일반 파일 산출물을 남긴다 — MCP도 CLI도
  없는 환경(챗창에 붙여넣는 사람 포함)까지 지원된다.

## 3. 아키텍처

### 3.1 컨텍스트 4계층

| 계층 | 내용 | 생산자 | 신선도 |
|---|---|---|---|
| 0 | `AGENTS.md`: 운영 규칙 | 사람 | 변경 시 |
| 1 | 리포맵: 랭킹된 파일 + 심볼 아웃라인 | 자동 생성 | 커밋/CI마다 |
| 2 | 모듈 문서(`docs/context/*.md`) + 모듈 팩 | 사람 + 생성 | 필요 시 |
| 3 | 심볼 검색(정의 + 참조) | 실시간 | 실시간 |

### 3.2 소비 프로파일

```yaml
profiles:
  frontier: { inject: [agents], budget: 4000 }
  mid:      { inject: [agents, repomap], budget: 24000 }
  light:    { inject: [agents-summary, repomap, target-files], budget: 12000 }
```

`light` 팩은 규칙을 앞에 놓고 뒤에 짧은 규칙 리마인더를 반복한다 — 긴
컨텍스트에서 모델은 프롬프트의 양 끝을 중간보다 훨씬 잘 기억하기 때문이다.

### 3.3 인터페이스 3중 구조

에이전트형 클라이언트를 위한 MCP 서버(도구 5종: `get_rules`, `get_repomap`,
`get_module_context`, `search_symbol`, `make_pack`); 터미널·훅·CI·파이프를
위한 CLI; 만능 폴백인 생성 파일. 셋 다 같은 코어를 노출한다.

## 4. 알고리즘과 실전 저장소의 교훈

리포맵은 교차 파일 심볼 참조로 파일을 랭킹한다(aider의 tree-sitter+PageRank
접근의 무의존 단순화 — 알고리즘 참고만, 코드 차용 없음). 심볼은 언어별 정규식
아웃라인으로 추출하며, 같은 인터페이스 뒤로 tree-sitter 어댑터가 교체
가능하다. 소스 308개 실전 저장소 온보딩이 합성 픽스처가 숨겼던 결함 3건을
드러냈고, 각각이 규칙이 됐다:

1. **테스트 파일 강등.** 모든 테스트가 참조하는 픽스처가 랭킹을 독점했다 —
   코드베이스를 파악하는 에이전트에게는 프로덕션 코드가 먼저다. 테스트 경로는
   0.2배, 자체 정의 가중치는 상한.
2. **내장 섹션 캡.** 캐시된 8K 토큰 맵을 12K 팩에 통째로 넣자 파일 원문
   섹션이 굶었다. 내장 섹션마다 예산 지분을 강제한다(맵 ≤ 예산/3, 최대 4K).
3. **예산이 자를 것을 랭킹하라.** 대상 파일이 알파벳 순이어서 잘림이 엉뚱한
   파일에 떨어졌다. 이제 참조 랭킹 순으로 배치해 잘림이 가장 덜 참조되는
   파일에 떨어진다.

## 5. 실측 결과

측정 3회(전체 데이터: [`eval/findings.md`](../eval/findings.md); 하네스
`eval/run.mjs`는 `ollama run …` 포함 stdin 프롬프트를 받는 어떤 모델 명령과도
동작). 과제는 제공된 컨텍스트로만 답할 수 있고, 모델 프로세스는 빈
디렉토리에서 실행돼 저장소를 읽을 수 없다.

**1차(합성 픽스처)와 2차(실전 308파일 저장소)** 는 같은 그림을 보였다
(과제 3개 통과율):

| | 소형 모델 | 상위 모델 |
|---|---|---|
| `mid` (규칙+맵) | 2/3 | 2/3 |
| `light` (+랭킹된 파일 원문) | **3/3** | **3/3** |

실패한 과제는 항상 구현 세부 질문이었고 — 두 모델 계층 모두에서 — 파일
원문이 포함되자 두 계층 모두 통과했다. **성패를 가른 것은 컨텍스트 형태이지
모델 등급이 아니다.** 특기할 점: 두 모델 모두 환각 대신 "컨텍스트에 없다"고
정직하게 답했다.

**3차 — 실사용 에이전트 세션**(실전 저장소, 파일 읽기 도구 차단, ctx-kit
MCP만): 4턴, 9.3초에 3/3 정답 — `get_rules`와 `search_symbol` 단 2회 호출.
프론티어 프로파일(최소 상시 규칙 + 온디맨드 검색)이 어떤 팩보다 적은 토큰으로
설계 그대로 작동했다.

1차에서 드러난 주의점 하나: 모델이 심볼 이름만으로 호출 관계를 *추론*해 맞힌
경우가 있었다. 이름이 좋은 코드에서만 성립하는 요행이며 근거가 아니다 — 호출
관계 질문은 맵이 아니라 3계층으로 보내야 한다.

## 6. 비용·안전 태세

- **유료 인프라 불필요.** 커밋 시점 게이트(`init --hooks`)는 로컬에서 무료로
  돌고, GitHub Actions 워크플로는 선택 사항이며 비공개 저장소에서 유료 분량을
  소모함을 명시한다.
- **시크릿 스캔.** `ctxkit check`는 LLM으로 가는 모든 것(규칙, 모듈 문서,
  생성 팩)에서 개인키 블록·클라우드 키·토큰형 대입을 탐지한다 — 팩이 바로
  외부 서비스에 붙여넣어지는 파일이기 때문이다.
- **외부 파일 보호.** `sync`는 손으로 쓴 도구별 규칙 파일을 덮어쓰기 거부한다.

## 7. 라이선스 태세

ctx-kit은 MIT. 외부 도구는 코드 차용 없이 CLI 실행으로만 통합해(어댑터 패턴)
라이선스 경계를 기계적으로 유지한다: Repomix(MIT)는 선택적 패커로, Serena(MIT)는
래핑하지 않고 3계층으로 *나란히* 등록, aider(Apache-2.0)는 알고리즘 참고만.
GPL 도구(universal-ctags 등)는 제외했다.

## 8. 관련 작업

AGENTS.md 표준(Linux Foundation); aider 리포맵(tree-sitter+PageRank);
Repomix·code2prompt(저장소→프롬프트 패커, MIT); Serena(LSP 기반 MCP 툴킷,
MIT); Ruler 등 규칙 배포 도구 — ctx-kit의 `sync`는 그 공통 부분집합을 무의존
내부 구현했다.

## 9. 한계와 로드맵

- 소형 모델 계층은 소형 API 모델을 대리로 측정했다. 진짜 로컬 LLM
  라운드(`--custom "ollama run …"`)는 로컬 설치 후 예정.
- 심볼 추출은 정규식 아웃라인 기반 — tree-sitter 어댑터 자리가 있다.
- 참조 카운트는 어휘적(단어 경계)이며 의미론이 아니다 — 의미론 쪽은 Serena가
  담당한다.
- 예정: 모듈 범위 맵, 토크나이저 정밀 예산, 대형 수작업 CLAUDE.md를
  AGENTS.md SSOT로 이관하는 2호 실전 온보딩.
