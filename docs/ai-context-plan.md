# AI 개발용 소스코드 컨텍스트 체계 기획

> **개발 목표**: AI로 개발되는 소스 저장소를 관리하고, 고성능부터 저성능까지 다양한
> AI 모델이 사용될 때의 규칙(rule)과 형태(form)를 관리하는 것.
>
> 목적: AI로 개발할 때 소스코드의 어떤 부분을 나열·정리해야 효과적인지 정의하고,
> AI 수준(Claude/Codex 같은 프론티어 모델 ~ 로컬 LLM)에 따라 의미 있게 동작하며,
> 다른 CLI·다른 저장소(source)에서도 참조 가능한 도구 중립적 구조를 만든다.

---

## 1. 설계 원칙

1. **단일 소스 오브 트루스(SSOT)**: 규칙·컨텍스트는 한 곳에만 작성하고, 각 AI 도구용 파일(CLAUDE.md, .cursorrules, GEMINI.md 등)은 자동 생성/심링크한다.
2. **코드에서 추론 가능한 것은 적지 않는다**: 빌드 명령, 아키텍처 결정, 불변식(invariant), 금지 사항 등 "코드만 봐서는 알 수 없는 것"만 문서화한다. 2026년 연구(138개 저장소 대상)에서 LLM이 자동 생성한 장황한 AGENTS.md는 오히려 작업 성공률을 낮추고 비용을 20% 이상 올렸다 — 사람이 검증한 최소 내용이 원칙.
3. **정적 문서(사람 작성) / 파생 산출물(자동 생성)의 분리**: 리포맵, 컨텍스트 팩은 코드에서 자동 재생성하며 절대 손으로 수정하지 않는다.
4. **AI 수준별 소비 프로파일**: 같은 원본에서 모델 능력에 맞는 분량·형태로 잘라 제공한다.
5. **표준 우선**: AGENTS.md(Linux Foundation 이관, Claude Code·Codex·Cursor·Aider·Copilot·Gemini CLI 등이 네이티브 지원)와 MCP(Model Context Protocol)를 채택해 특정 벤더에 종속되지 않게 한다.

## 2. 정리해야 할 소스코드 정보의 4계층

### Tier 0 — 운영 규칙 (사람 작성, 항상 주입, ~150줄 이하)
파일: `AGENTS.md` (저장소 루트, 필요 시 하위 디렉토리별 추가)

| 항목 | 내용 |
|---|---|
| 빌드/테스트/실행 명령 | 정확한 커맨드 한 줄씩 |
| 코드 스타일 중 린터로 강제 불가한 것 | 네이밍 의도, 계층 간 의존 방향 등 |
| 아키텍처 결정(ADR 요약) | "왜 이렇게 되어 있는가" 링크 포함 |
| 금지/주의 사항 | 건드리면 안 되는 파일, 배포 관련 제약 |
| 도메인 용어집 | 코드 식별자 ↔ 업무 용어 매핑 |

제외: 일반적 모범 사례("클린 코드 작성"), 파일 전체 목록, 언어 표준 컨벤션.

### Tier 1 — 구조 맵 (자동 생성, 압축 컨텍스트)
- **리포맵**: tree-sitter로 심볼(클래스·함수 시그니처)을 추출하고 참조 그래프에 PageRank를 적용해 중요도 순으로 토큰 예산 안에 채우는 방식(aider의 repomap 방식).
- 산출물: `docs/generated/repomap.md` — 로컬 LLM에게는 이것이 "코드베이스 전체를 아는" 유일한 수단이 된다.
- 디렉토리 트리 + 모듈별 한 줄 책임 설명도 함께 생성.

### Tier 2 — 모듈 컨텍스트 (사람 작성, 필요 시 로드)
- `docs/context/<모듈명>.md`: 모듈별 데이터 흐름, 핵심 불변식, 외부 연동, 대표 진입점 파일 경로.
- 각 문서는 독립적으로 읽혀야 함(로컬 LLM은 여러 문서를 동시에 못 올림).

### Tier 3 — 온디맨드 시맨틱 검색 (도구 제공, 실시간)
- LSP 기반 심볼 검색·참조 추적(find_symbol, find_referencing_symbols)을 MCP 서버로 노출.
- 컨텍스트에 미리 넣는 대신, 에이전트가 필요한 심볼만 그때그때 가져오게 한다. 프론티어 모델에 가장 효율적.

## 3. AI 수준별 소비 프로파일

| 구분 | 예시 | 컨텍스트 전략 |
|---|---|---|
| **프론티어 (도구 사용 능숙)** | Claude Code, Codex | Tier 0만 상시 주입 + Tier 3(MCP 시맨틱 검색)으로 스스로 탐색. Tier 1/2는 링크만 제공 |
| **중간 (도구 사용 가능, 컨텍스트 32~128K)** | 로컬 Qwen3 14B급, 중형 API 모델 | Tier 0 + Tier 1(리포맵) 상시 주입, Tier 2는 작업 대상 모듈 것만 |
| **경량 (도구 사용 불안정, 컨텍스트 ≤32K)** | 소형 로컬 LLM | 작업 범위에 맞춰 미리 잘라낸 **컨텍스트 팩**(Repomix 부분 출력 + Tier 0 요약 + 대상 파일 원문)을 프롬프트에 직접 포함. 중요 내용은 팩의 앞·뒤에 배치(중간 40K~80K 구간 회상률 저하 문제 회피) |

프로파일은 `context.config.yaml` 하나로 정의해 두고, 생성 스크립트가 `--profile frontier|mid|light`로 각 산출물을 만든다.

## 4. 크로스 툴 · 크로스 저장소 참조 구성

### 4.1 다른 CLI에서 참조 (도구 중립)
- 원본: `.ruler/` 또는 `AGENTS.md` 하나만 유지.
- **Ruler**(또는 유사 도구)로 CLAUDE.md, .cursorrules, GEMINI.md, copilot-instructions.md 등 30+ 도구 포맷으로 자동 배포. 심링크 방식(agentsync)도 대안.
- 시맨틱 검색은 MCP 표준이므로 Claude Code, Codex CLI, Cursor, 로컬 에이전트(OpenCode 등) 어디서든 같은 서버를 붙여 쓴다.

### 4.2 다른 저장소(source)에서 참조
- 이 프로젝트를 **템플릿 + CLI 패키지**로 만든다:
  - 공통 규칙·스키마·생성 스크립트는 이 저장소에 두고, 각 대상 저장소는 (a) git submodule / (b) npm·pip 패키지 / (c) `npx <도구> init` 스캐폴딩 중 하나로 가져다 쓴다.
  - 대상 저장소에는 얇은 설정 파일(`context.config.yaml`)과 산출물만 남고, 로직은 전부 여기서 버전 관리.
- Repomix·code2prompt는 원격 저장소 URL 대상 실행을 지원하므로, 다른 저장소의 컨텍스트 팩도 중앙에서 생성 가능.

## 5. MIT 라이선스 오픈소스 도입 검토

| 도구 | 역할 | 라이선스 | 판단 |
|---|---|---|---|
| **Repomix** | 저장소 → 단일 AI 친화 파일 패킹, 토큰 카운트, Secretlint 시크릿 검사 | MIT | ✅ 도입 (경량 프로파일 컨텍스트 팩 생성기) |
| **code2prompt** | 코드베이스 → 프롬프트 변환, Handlebars 템플릿, glob 필터, MCP 서버 | MIT | ✅ 도입 (프로파일별 템플릿 커스텀에 유리, Repomix와 택1 또는 병용) |
| **Serena** | LSP 기반 시맨틱 검색/편집 MCP 서버, 30+ 언어 | MIT | ✅ 도입 (Tier 3 담당) |
| **Ruler** | 단일 규칙 → 30+ 에이전트 설정 파일 배포 | MIT 계열로 알려짐 — 도입 전 저장소에서 재확인 | ✅ 유력 (4.1 담당) |
| aider (repomap) | tree-sitter+PageRank 리포맵 원조 구현 | Apache-2.0 (MIT 아님) | ⚠️ 알고리즘만 참고. 코드 차용 시 Apache 고지 의무 |
| RepoMapper | aider repomap의 독립 구현 + MCP 서버 | 도입 전 확인 필요 | 보류 — 라이선스 확인 후 Tier 1 후보 |
| universal-ctags | 심볼 인덱스 | GPL | ❌ 제외 (MIT 정책과 충돌 소지) |

> 라이선스는 조사 시점 기준이며, 실제 도입 직전에 각 저장소의 LICENSE 파일을 다시 확인한다.

## 6. 목표 디렉토리 구조 (템플릿)

```
repo/
├── AGENTS.md                  # Tier 0 원본 (표준, 모든 도구가 읽음)
├── CLAUDE.md → AGENTS.md      # Ruler/심링크로 자동 생성
├── context.config.yaml        # 프로파일·모듈 경계·토큰 예산 정의
├── docs/
│   ├── context/               # Tier 2: 모듈별 사람 작성 문서
│   └── generated/             # Tier 1 + 경량 팩 (자동 생성, git 커밋 여부 선택)
│       ├── repomap.md
│       └── packs/<모듈>-light.md
└── scripts/
    └── gen-context.{sh,ts}    # Repomix/code2prompt 호출 래퍼, CI에서 재생성
```

## 7. 실행 로드맵

1. **P0**: `AGENTS.md` 초안 작성(150줄 이하, 사람 검증) + Ruler로 CLAUDE.md 등 배포 확인.
2. **P1**: Repomix/code2prompt 도입, `gen-context` 스크립트로 Tier 1 리포맵과 경량 팩 자동 생성. CI에서 코드 변경 시 재생성.
3. **P2**: Serena MCP 서버 연동 → Claude Code / Codex CLI / 로컬 에이전트에서 동일하게 동작 검증.
4. **P3**: 템플릿을 별도 배포 가능한 패키지로 분리, 다른 저장소 2곳에 적용해 크로스 리포 검증.
5. **P4**: 프로파일별 성능 측정(같은 작업을 프론티어/중간/경량 모델로 수행해 성공률·토큰 비용 비교) 후 토큰 예산 튜닝.
