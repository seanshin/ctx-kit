# ctx-kit: Capability-Tiered Codebase Context for AI Coding Agents

*Whitepaper · v0.2.0 · September 2026 · [한국어판](WHITEPAPER.ko.md)*

## Abstract

Repositories developed with AI assistance are consumed by models of very
different capability: frontier agents that explore with tools, mid-size models
with 32–128K windows, and small local LLMs that receive a single pasted
prompt. ctx-kit maintains one source of project context and serves each model
tier a form it can use, through three interfaces (MCP server, CLI, plain
files). In controlled measurements on both a synthetic fixture and a 308-file
production repository, task success was determined by **context form rather
than model grade**: implementation-detail tasks failed on all model tiers
without file contents and passed on all tiers with them, while a frontier
agent solved the same tasks with two targeted MCP calls and no bulk context.

## 1. Problem

Three observations motivated the design:

1. **Model heterogeneity is permanent.** Cost, privacy and latency guarantee
   that small local models will keep being used alongside frontier agents on
   the same codebase. Context tooling that assumes one consumption style
   (tool-driven exploration, or one big pasted file) fails the other.
2. **Context files are being written badly at scale.** Published evaluation of
   LLM-generated agent-instruction files across 138 repositories found they
   *reduced* task success while raising inference cost by over 20%. Rules must
   be short, human-verified, and restricted to what code cannot express.
3. **Tool lock-in is avoidable.** The AGENTS.md convention (now under the
   Linux Foundation, read natively by Claude Code, Codex CLI, Cursor, Copilot,
   Gemini CLI and others) and the Model Context Protocol make a
   vendor-neutral design practical.

## 2. Design principles

- **Single source of truth.** Rules live in `AGENTS.md` only; per-tool files
  (`CLAUDE.md`, `.cursorrules`, …) are generated copies or symlinks. A synced
  file that was not generated by ctx-kit is never overwritten without
  `--force`.
- **Write only what code cannot tell.** Commands, constraints, invariants,
  domain glossary; ≤150 lines, enforced by the gate.
- **Human-authored vs. derived, strictly separated.** Maps and packs are
  regenerated from code and never hand-edited.
- **Capability profiles.** One config declares, per model tier, which
  sections to inject and under what token budget.
- **Files are the floor.** Every feature must leave a plain-file artifact, so
  an environment with no MCP and no CLI — including a human pasting into a
  chat window — is still served.

## 3. Architecture

### 3.1 Four context tiers

| Tier | Content | Producer | Freshness |
|---|---|---|---|
| 0 | `AGENTS.md`: operating rules | human | on change |
| 1 | Repository map: ranked files + symbol outlines | generated | per commit/CI |
| 2 | Module docs (`docs/context/*.md`) + module packs | human + generated | as needed |
| 3 | Symbol search (definitions + references) | live | real time |

### 3.2 Consumption profiles

```yaml
profiles:
  frontier: { inject: [agents], budget: 4000 }
  mid:      { inject: [agents, repomap], budget: 24000 }
  light:    { inject: [agents-summary, repomap, target-files], budget: 12000 }
```

`light` packs place rules at the front and repeat a short rule reminder at the
back, because long-context models recall the edges of a prompt far better than
the middle.

### 3.3 Three interfaces

MCP server (five tools: `get_rules`, `get_repomap`, `get_module_context`,
`search_symbol`, `make_pack`) for agentic clients; CLI for terminals, hooks,
CI and pipes; generated files as the universal fallback. All three expose the
same core.

## 4. Algorithms and lessons from a real repository

The repository map ranks files by cross-file symbol references (a
dependency-free simplification of aider's tree-sitter + PageRank approach;
algorithm inspiration only, no code reuse). Symbols are extracted by
per-language regex outlines behind an interface a tree-sitter adapter can
later replace. Onboarding a 308-file production repo surfaced three defects
that synthetic fixtures had hidden — each is now a rule:

1. **Demote test files.** Fixtures referenced by every test dominated the
   ranking; an agent orienting itself needs production code first. Test paths
   are scored ×0.2 and self-definition weight is capped.
2. **Cap embedded sections.** A cached 8K-token map pasted whole into a
   12K-token pack starved the file-contents section. Every embedded section
   gets a hard share of the budget (map ≤ budget/3, max 4K).
3. **Rank what the budget will cut.** Target files were emitted
   alphabetically, so the cut fell on the wrong files. They are now emitted in
   reference-rank order, making the budget cut fall on the least-referenced
   files.

## 5. Empirical results

Three measurement rounds (full data: [`eval/findings.md`](../eval/findings.md);
harness: `eval/run.mjs`, works with any stdin-reading model command including
`ollama run …`). Tasks are answerable only from the supplied context; model
processes run in an empty directory so they cannot read the repo.

**Round 1 — synthetic fixture, and Round 2 — 308-file production repo** gave
the same picture (pass rate over 3 tasks):

| | small model | larger model |
|---|---|---|
| `mid` (rules + map) | 2/3 | 2/3 |
| `light` (+ ranked file contents) | **3/3** | **3/3** |

The failing task was always the implementation-detail question, on both model
tiers; both tiers passed it once file contents were included. **Context form,
not model grade, decided success.** Notably, both models answered "the context
does not contain this" rather than hallucinating.

**Round 3 — live agent session** on the production repo (file-reading tools
disabled, ctx-kit MCP only): 3/3 correct in 4 turns, 9.3 seconds, using just
`get_rules` and one `search_symbol` call — the frontier profile (minimal
standing rules + on-demand search) operating exactly as designed, at a
fraction of the token cost of any pack.

One caution surfaced in Round 1: models sometimes *inferred* call-graph
answers correctly from symbol names alone. That is name-quality luck, not
evidence; call-graph questions should be routed to Tier 3, not answered from
the map.

## 6. Cost and safety posture

- **No paid infrastructure.** The commit-time gate (`init --hooks`) runs
  locally and free; the GitHub Actions workflow is optional and labeled as
  consuming paid minutes on private repos.
- **Secret scanning.** `ctxkit check` scans everything destined for an LLM
  (rules, module docs, generated packs) for private-key blocks, cloud keys
  and token-shaped assignments — packs are exactly the files that get pasted
  into external services.
- **Foreign-file protection.** `sync` refuses to overwrite hand-written
  per-tool rule files.

## 7. License posture

ctx-kit is MIT. External tools are integrated by CLI invocation only, never
code reuse (adapter pattern), keeping the license boundary mechanical:
Repomix (MIT) as an optional packer; Serena (MIT) registered *alongside* as
the LSP-grade Tier 3 rather than wrapped; aider (Apache-2.0) served as
algorithm reference only. GPL tools (e.g. universal-ctags) were excluded.

## 8. Related work

AGENTS.md convention (Linux Foundation); aider repository maps (tree-sitter +
PageRank); Repomix and code2prompt (repo-to-prompt packers, MIT); Serena
(LSP-based MCP toolkit, MIT); Ruler and similar rule-distribution tools —
ctx-kit's `sync` implements the common subset internally with zero
dependencies.

## 9. Limitations and roadmap

- The small-model tier was measured with a small API model as proxy; a true
  local-LLM round (`--custom "ollama run …"`) is pending local install.
- Symbol extraction is regex-outline based; a tree-sitter adapter slot exists.
- Reference counting is lexical (word-boundary), not semantic; Serena covers
  the semantic end.
- Planned: per-module map scoping, tokenizer-accurate budgets, a second
  production onboarding that migrates a large hand-written CLAUDE.md into the
  AGENTS.md SSOT flow.
